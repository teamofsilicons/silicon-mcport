Manual testing found two repaired defects: duplicate browser `Set-Cookie` headers were being overwritten, and sentence-ending punctuation was included in returned asset URLs. Both flows were repeated successfully after the fixes. Activity's full-result fetch and persistent navigation were also verified after their updates.

Evidence is retained locally under ignored `.local/e2e/manual/` and `.local/e2e/assets/`. Relevant files include `cloudflare-result.json`, `browser-share-tools.json`, `official-files-tools.json`, `allowed-files/silicon-created.txt`, `tool-result.json`, `byte-proof.json`, and downloaded assets. Browser screenshots, where captured, are under `docs/testing/screenshots/`.

Automated checks supplement this manual pass: the real-binary fixture journey passed 62 assertions for roles/access, shared/per-user accounts, OAuth PKCE, HTTP/stdio relay, cancellation, no replay, lifecycle isolation and assets. The unified check passed 63 Rust tests (including the client doctest), strict Clippy, formatting, 24 web tests, 6 package-validator tests, 3 protocol-fixture tests and the production website build. Controlled OAuth and loopback Postmark tests are not proof of live provider OAuth or delivered mail.

The optimized macOS ARM64 CLI was staged and validated in `.local/native/mcport-macos-aarch64.zip` (SHA-256 `eb2e05f0e502fd5b6b90ee519bd8fa10d083bc2109dbe32cb9d57fea0416b9a2`). It was unpacked into a fresh install location and used with a new `SILICON_HOME`: pre-login IAM discovery, fixture Silicon login, a shared local HTTP call returning `desktop-owner`, and a real Cloudflare documentation search all passed. This is one native candidate, not a complete six-target Honeycomb release.

Still unverified: production Honeycomb/IAM registration and deployment; physical Figma (the local port 3845 probe refused connection); two separate physical hosts; live authenticated provider OAuth; production mail/telemetry delivery; and execution/install on the five native targets other than the local macOS ARM64 environment. Browser save-to-disk remains unverified as described above.
